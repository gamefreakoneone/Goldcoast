# Design: hosted deployment

Use CDK Python pinned to current stable 2.269.0 and constructs10. CloudFront serves a private S3 web bundle via OAC and routes /api/v2/* to a VPC origin backed by internal ALB. API behavior disables caching, forwards Authorization/query/required headers and supports SSE with heartbeats. Hash routing avoids SPA API-error rewrites. Cognito callback/logout URLs derive from the distribution hostname; create distribution/ALB before client and tasks to avoid cycles. Public Fargate task interfaces supply outbound provider access without a paid NAT gateway; security groups allow API ingress only from the private ALB and no worker ingress. RDS/EFS remain isolated. Two AZ VPC; one small API task and one 0.5vCPU/2GB worker; one small single-AZ encrypted Postgres16 database for demo. No HA claim.

S3AssetStore replaces local bytes through the existing AssetStore interface and strictly scopes tenant/id keys. EFS access point mounted at the worker recordings directory preserves every model/provider artifact across task replacement. Secrets are generated/provisioned through Secrets Manager; deployment script uploads provider keys from local .env without console output or template literals. Database connection URL is assembled inside the app from injected secret components with sslmode=require. API gets DB secret only; worker gets provider secrets. Cognito JWT validation uses verified access-token claims and groups; new users start zero live grants. Owner/demo groups configured with no public registration.

Dockerfile Python3.12 includes pinned app dependencies, Chromium/ffmpeg and packaged replay, runs nonroot, exposes only studio API by default. Migration ECS task uses the same image. API/worker services default to zero desired tasks until migration and secret configuration complete; deploy script activates them afterward. Readiness checks database access; logs exclude secrets; retention7days. CDK outputs frontend URL, pool/client, cluster/services/migration/network IDs, buckets and secret ARNs. CLI helper uses boto3 for identity/outputs/deployment follow-up and invitations, no email messages sent automatically. Explicit identity/account review before provisioning.
