# Design: discovery and knowledge graph

Add studio/discovery.py and studio/graph.py. EvidenceSource has deterministic URL ID, title, bounded text, retrieval/expiry timestamps and provider. ProviderCassette caches exact request signatures, writes pending before calls, completed/failed afterward, records duration and bounded response, and replays without constructing HTTP clients. Unknown/failed records require a new explicitly authorized workflow. Tavily basic search uses max_results=5, no generated answer/raw content and usage reporting; extraction is one known URL per reservation. Optional Ticketmaster Discovery events use the same search budget and return normalized source text.

Discovery exposes typed search/extract methods and Strands tools with explicit JSON schema descriptions. The worker will pass them to scouts in 0013. Sources merge by canonical URL with tracking parameters removed. GraphClaim includes subject, predicate, value, source ID, exact quote and optional validity deadline. Validation rejects unsupported citations; graph building deduplicates equal claims, preserves contradictory values, and creates entity-to-source supports edges. A graph is a versioned resource document, not a second database service. Existing PostgreSQL JSON resource persistence is sufficient for this hackathon graph size. Cap sources at 40 and claims at 80. Graph API and orchestration arrive with the workflow spec.
