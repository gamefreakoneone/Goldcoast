# Design: business and brand onboarding

Add studio/brand.py with strict Pydantic BusinessProfile, Product, Offer, BrandKit and AssetMetadata models plus BrandService. Store them in the existing versioned resources table. A tenant has one active business profile and brand kit; asset rows have immutable content and business ID. Asset bytes are stored by opaque resource IDs through AssetStore. Validate images with Pillow, transcode to PNG to strip metadata, reject animation and dimensions above 16 megapixels. PDF files must have a PDF signature and remain inert provider inputs/downloads; fonts require recognized binary signatures. Cap individual files at 10MB, total 30 assets and 100MB per tenant. Accept only explicit role/MIME pairs. URLs in profiles are data, not fetch targets.

Mount authenticated /api/v2/business, /brand, /assets endpoints through a separate router using existing identity dependency. PUT bodies carry expected version to prevent lost edits. Uploads require multipart role, file and rights confirmation. GET asset content verifies tenant and metadata, sets nosniff and attachment for non-images. Brand analysis helper accepts a recorded Gemini client, exact asset parts and typed schema; it emits a draft with confirmed=false. The worker that reserves and invokes analysis is delivered in 0013. Owner confirmation is a separate explicit brand save; model output cannot set it. No public path or provider key is returned.
