# Design: adaptation and replay

Commit data/studio_demo/campaign.json plus private-package PNG files, hashes and manifest from the actual completed live run. A validated package loader uses a fixed configured directory and reads only confined named files. POST /api/v2/replays/sample creates an idempotent owned replay job with the packaged immutable snapshot; worker imports its typed campaign checkpoint and copies creative media into independent tenant-scoped resources with decisions reset. Existing owned replay copies source creatives similarly. Do not copy inherited creative IDs. A replay flag and job mode are both required to bypass current-business freshness checks; API/ZIP/UI label historical content explicitly. No provider factory is invoked. Events replay stored stages and completion without pretending tools ran live.

Persist singleton schedule as a versioned Resource using existing row locking. Schedule fields: enabled false, local hour 0..23, goal, last_local_date, last_job_id, last_error. API accepts only editable fields and expected version. Worker tick scans enabled schedules; on/after local hour reserve a deterministic schedule ID/account/date via existing job idempotency, then records the outcome. Cross-worker duplicate starts resolve to one job. Require current profile/brand before job reservation. Disabled global controls or depleted grants produce a visible status; retry on later ticks is safe and bounded by job idempotency. Schedule errors must not leak secrets. Snapshot edits invalidate old live approvals and next scheduled campaign uses newest confirmed snapshot.

UI Today adds Try recorded example (free) for every account and keeps owned replay selection. Settings adds an explicit daily schedule form and explanation of allowance use. Replay reviews show source date and historical status; export manifest includes replay:true. Update README with judge replay walkthrough.
