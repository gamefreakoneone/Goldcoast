# Design: chief marketing workflow

Add studio/workflow.py (typed search plan, scout reports, candidates and chief decision), studio/worker.py (claim, heartbeat, execute), and api/workflow_routes.py. Each stage writes a pending checkpoint before execution and a completed JSON output after success. A pending stage on recovery fails safely; completed stages are reusable. Worker heartbeats renew only the lease, preserving checkpoint writes. Runtime budget callbacks reserve durable counts with worker identity. Full model recordings stay private on disk; SSE emits concise agent/tool lifecycle information.

The chief planner outputs at most two queries per scout. Each scout has Tavily search/extract tools and returns typed claims plus candidate ideas. Build a graph and reject candidates referencing missing/disputed/stale sources or products outside the owner profile. The chief chooses only among validated candidates. If evidence is insufficient, use a clearly labeled evergreen idea using a real product. Selection carries the graph source IDs and cannot invent a candidate. Optional Ticketmaster event sources enter the local scout context. Optional video analysis is limited to one recorded call and feeds visible cues/search queries into the planner; it does not establish personal attributes.

POST /api/v2/workflows accepts mode, goal, optional video asset, replay source and Idempotency-Key. POST /api/v2/brand/analyze reserves brand jobs. Snapshots include profile/brand IDs, versions, documents, asset metadata and local date. GET /runs/{id}/result and /graph are tenant scoped. Existing jobs/events endpoints provide history and cancellation. The worker is `python -m goldcoast.studio.worker`, with --once for validation. Studio recordings are under output/studio/runs/<tenant>/<job>. Providers load keys only for live work. Replay copies typed completed stage outputs from an owned terminal job, never constructs model/search clients.
