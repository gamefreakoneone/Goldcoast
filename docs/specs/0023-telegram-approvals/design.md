# Design

New internal start_campaign started_via keyword is studio|telegram, default studio, written into new job inputs. WorkflowStart does not accept it. job_view exposes normalized started_via; missing historical metadata uses established telegram: and telegram-campaign: request-key prefixes. Existing inputs/digests are never backfilled. GET /runs/{job_id}/revisions returns typed RevisionSummary entries (id, parent_id, state, created_at, started_via) in chronological order for the owned campaign family. Parent traversal and descendant expansion use only the current tenant's campaign rows, independent of the history page limit. Missing/foreign requested jobs retain existing access errors.

The visible polling hook coalesces focus, prevents overlapping polls, aborts on hide/unmount and resumes immediately on focus/visibility. Campaign history refreshes runs and usage even while idle, preserving profile data and discarding stale list responses. Review independently polls revision summaries; it shows parent/original/latest navigation without switching the current version, along with its feedback and origin. Telegram regeneration confirmation links to the new run.

CreativeVerdict retains optional rubric_version and ScoreReasons for historical compatibility. New JudgedVerdict requires literal 2026-09-v1 and four nonempty image-specific reasons. Shared judge_prompt supplies the same anchored rubric, business, brand kit, exact brief, selected idea, evidence and testimonial context to both producers, followed by final pixels and labeled references. Score 7 is acceptable with weaknesses, 8 strong, 9 excellent, and 10 has no identifiable defect in that criterion; no score quotas. Critical defects must be listed and scored below seven. Existing passing requires all four scores at least seven and no critical issues. Historical scores are not rewritten.

scripts/calibrate_studio_judge.py prepares six inspectable cases from two owned saved posts. It mutates only copies: unsupported free-offer banner, replacement product, clipped headline and nearly invisible copy. --live makes at most one call per case, guarded by durable exclusive attempt markers before dispatch. Ambiguous attempts are never automatically retried. Independent private recordings and a report retain model, latency, verdict and token usage; no workflow, grant or decision is mutated.

The worker registers start, commands, campaign, status and credits through setMyCommands once on startup; registration failure does not stop polling. Commands resolve the current linked chat and refuse missing or ambiguous account links. Help works before linking. /campaign requires enabled notifications and uses start_campaign with WorkflowStart(mode=live, creative_type=auto, include_story=false), an optional brief capped at 1500 characters, and durable telegram-campaign:<update_id> idempotency. Replayed updates cannot spend another grant, including a crash after reservation but before sending confirmation. /start without a code never generates. /status returns the latest campaign and Review link; /credits reports account/shared allowances and live availability. Source URLs remain in asset metadata and classification editing, with no attribution link on cards.

StudioSettings reads telegram_token (excluded from repr/serialization) and telegram_bot_link. TelegramClient uses injected httpx transport, ten-second requests, thirty-second getUpdates read timeout with timeout=20, no automatic sends/retries, and sanitized errors. Notifications are side effects, not provider recordings.

NotificationService persists typed NotificationSettings, PendingPrompt and link data as tenant Resources. Public notification view excludes pending/internal data. GET /notifications/config returns configured; GET /notifications returns the connection or null; POST /notifications/telegram/link returns code/deep_link; DELETE /notifications/telegram removes connection and links; PUT /notifications accepts enabled. Codes are cryptographically random eight-character single-use tokens with ten-minute expiry. Lock tenant/connection updates to avoid overwriting pending prompts. Callbacks resolve ownership server-side and require the current linked chat. Pending prompts are keyed by chat and prompt message; reject uses ForceReply plus separate inline Skip message.

Worker starts one daemon TelegramPoller, using Repository sessions and persisted Controls.telegram_offset (new Alembic revision). Durable update receipt Resources are claimed before side effects, giving conservative at-most-once processing across crashes; do not repeat ambiguous effects. Persist update_id+1 after handling. A crashed claimed update may require a new explicit owner action, never silently consume another credit. No bot HTTP calls occur inside database transactions. Producers checkpoint notification_ready after creative_result; process_job dispatches after terminal completion. Emit notification_sent/notification_failed with sanitized fields; cap photos at six. One local worker only.

CreativeArtifact gains decided_via: studio|telegram default studio; decide accepts via and enforces completed/passing/current/pending conditions for Telegram, retaining existing studio behavior. Review polls visible completed jobs every three seconds/on focus and labels phone decisions. Replay resets decided_via.

WorkflowStart gains regenerate_from and owner_feedback (max 500). Regeneration requires live mode and a completed owned campaign, compares current business/brand IDs and versions, validates selected idea/testimonial before allowance reservation, reuses snapshot/goal/campaign/creative options, and uses repo.create_job with telegram:<update_id> for idempotency. Selected campaign takes precedence over product shortcut at execution. Directors receive bounded owner feedback as requested changes only; refinement prompts prepend it. Old decisions remain independent.

Captions use escaped HTML: business/placement/dimensions, headline, bounded copy, four judge scores, optional signal and citation count, business-local validity, studio review URL and compressed-preview/full-resolution ZIP footer. Reserve annotation space. Approve/reject buttons occupy the first row; regenerate occupies the second. Settings renders disabled/not connected/connected states, link fallback, enabled toggle and disconnect, with three-second pending-link polling and cleanup.
